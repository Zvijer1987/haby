# Contributing to Haby

Thanks for contributing to Haby.

## Ground rules

- Keep all repository-facing text in English
- Keep comments calm, short, and descriptive
- Prefer full-file changes over fragmented patches when updating deployment examples
- Keep UI labels consistent with the product vocabulary already used in the app
- Avoid introducing third-party branding into the core product copy

## Development workflow

1. Install workspace dependencies
2. Run the client and server in development mode
3. Make focused changes
4. Build the client before opening a pull request
5. Test the affected flow manually

## Code style

- Use TypeScript consistently
- Keep functions small and direct
- Prefer explicit naming over clever abstractions
- Write comments only when they explain intent, not obvious syntax

## Pull requests

Please include:

- a short summary
- screenshots for visible UI changes
- notes about any data or schema changes
- notes about any security-sensitive changes
